# 设计：输入过滤开关在 TUI 里的呈现（模型页设置块）

## 1. 位置与依赖

开关放在**模型页右栏的「选中模型设置」块**里 —— 和模型列表同一屏，不用记键、不用弹窗。

容器（右栏设置块、焦点区域、页脚）由 `10-18-tui-log-page` 落地：它把右下角常驻的日志搬去独立的日志页，腾出右栏。本任务负责设置块里的**四行过滤开关**及其写盘 / 生效行为。

块内容（本任务只负责前四行）：

```
╭ 选中模型设置 ──────────────╮
│ 图片过滤  关               │
│ 音频过滤  关               │
│ 文件过滤  关               │
│ 视频过滤  关               │
│ ─────────────────────────  │
│ warp 模式  按客户端请求 ▸   │   ← 全局开关，由日志页任务落地
╰────────────────────────────╯
```

## 2. 交互

- `←→`：模型列表 ↔ 设置块（由日志页任务实现焦点切换）。
- `↑↓`：在设置块内选行（过滤四行 + 模式行；到边界不越界）。
- `Enter`：过滤行 = 切换该类型的开 / 关；模式行 = 进确认流（另一个任务）。
- 没有单独的面板、没有新键：`Enter` 在模型行是「切换模型」，在设置行是「改开关」，靠当前高亮行区分。

## 3. 写盘与生效

- `src/config.ts` 的 `setTargetInputFilter(name, model, filter)` 写 `providers.<p>.targets.<m>.inputFilter`；沿用 `modify` + `applyEdits` + `FORMAT`，保留注释与其他键。
- **四项一起写**：按层生效，只写一项会让其他三项按 false 生效、静默关掉用户没碰的类型。切换某一项时以当前生效值为基线整体落盘。
- 顺序与 `applyRoutingMode` 一致：先写配置文件，再 `adminRequest("POST", "reload")`；写盘失败则保持旧值 + 反馈区报错（不假装成功），reload 失败保留已写入的配置并如实说明。
- 反馈文案：`图片过滤已开 · ark/doubao-seed-1-6`。

## 4. 显示语义

- 显示**这个模型实际生效的值**，不显示原始配置文本。
- 只认模型级与端点级：**不给供应商层做条目**（`providers.<p>.inputFilter` 这种统一开关不提供），所以设置块里没有「继承」这类标记 —— 不做概念区分，模型就是模型。
- 模型在配置文件里另有端点级配置时，块底写一行 dim 提示：`该模型还有端点级配置（配置文件里），这里只改模型级`，且不去动它们。
- 端点级覆盖了模型级时，对应行标「被端点级覆盖」，但仍可改模型级（改完对没有端点级配置的路径立即生效）。

## 5. 自动刷新

- `refresh()` 重建 state 时按模型名重算设置块内容；`settingsCursor` 是纯视图状态，刷新后保留；选中的模型消失则光标收敛回列表。

## 6. 边界

| 情况 | 行为 |
|---|---|
| daemon 未运行 | 配置照写，reload 失败进反馈区；设置块按配置显示新值 |
| 写盘失败（权限 / 磁盘） | 保持旧值并报错，不假装成功 |
| 模型在刷新后消失 | 光标收敛回列表 |
| 模型有端点级配置 | 块底提示，不修改这些配置 |

## 7. 文档与 spec

- `.trellis/spec/frontend/interaction-guidelines.md`：模型页设置块一节（四行 + 模式行、`←→` 焦点、写盘与生效语义）—— 与日志页任务的改动合并成一次。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 四项一起写被误认为「改了别的类型」 | 以生效值为基线，只有用户点的那一项变；反馈事件只报那一项 |
| 端点级配置遮蔽模型级 | 那一行标「被端点级覆盖」，并在块底说明只改模型级 |
| 与日志页任务的焦点改动冲突 | 容器与焦点归日志页任务，本任务只填四行内容，按依赖顺序落地 |
