## 2. 状态机改动（`src/tui/model.ts`）

- `TuiPage`：`"models" | "routing" | "providers" | "stats"` → `"models" | "providers" | "stats" | "runtime"`；`TUI_PAGES` 同步。
- `TuiFocus`：`"nav" | "list" | "daemon"` → `"nav" | "list" | "panel"`。语义变成「当前页的右栏 / 详情区」：模型页 = 选中模型设置，运行页 = 守护进程 + 重启按钮，供应商 / 统计页保持现在的行为（供应商页右侧仍是守护进程信息；统计页右栏仍是总计块）。
- 移除 `routingSelected` / `ROUTING_OPTIONS` / `beginRouting*` / `selectedRouting`，改为设置块里的一行：`settingsCursor` 的最后一行是 `"mode"`，`Enter` 走 `beginRoutingConfirm` 的确认流（确认文案不变）。
- 新增 `SETTINGS_ROWS` 内容定义，本任务只放一行 `["mode"]`；四行过滤由 `10-18-input-media-filter` 前置追加（`["image","audio","file","video","mode"]`），思考强度由 `10-18-reasoning-level-switch` 插在 `mode` 之前。
- 运行页的 `↑↓` 在页内不做选择（内容只读），`←→` 只在「页内容 ↔ 重启按钮」之间切焦点。

## 3. 渲染（`src/tui/render.ts`）

- 新增 `runtimePanels(state, height, width)`：按「守护进程 → 指标 → 反馈 → 请求活动」顺序铺满整页；高度不足时先砍活动条数、再砍反馈条数，并显示 `… 另有 N 条未显示`。重启按钮与三行指标永远保留。
- 模型页右栏换成 `settingsRows` 面板（过滤四行 + 分隔线 + 模式行）。
- 供应商页 / 统计页的右栏维持现状（供应商页继续显示守护进程信息，统计页显示总计块），避免一次改太多。
- 页脚按页切换文案；模型页出现 `Enter 切换/开关`，运行页出现 `Enter 重启 daemon`（焦点在重启按钮时）。

## 4. 自动刷新

- 现有 `refresh()` 重建 state 的机制不变：`page`、`focus`、`settingsCursor`、`statsWindow` 都要按旧快照恢复；`routing` 相关的恢复分支删掉，换成「模型页设置块的光标」。
- 反馈事件（`state.events`）继续在重建后回填，不被刷新清掉。

## 5. Spec / 文档同步

- `.trellis/spec/frontend/interaction-guidelines.md`：

  - 删除「模式页」相关段落，键位表里 `Enter` 的说明更新。
- `README.md` / `docs/README.zh-CN.md`：TUI 一节改四页说明、模式位置、运行页。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 改动面大：导航、焦点、渲染、现有 tui 测试大量依赖「模式页」 | 先改状态机 + 渲染跑测试，再改文案；模式页相关用例整体改写而不是删除（同样的确认流，换位置） |
| 运行页内容多，矮终端截断后看不出关键信息 | 固定优先级：重启按钮 → 指标 → 反馈 → 活动；截断给条数提示 |
| 右栏语义从「守护进程」变成「页详情区」 | 各页详情区在 spec 里逐页写明，测试逐页断言 |
| 用户以为模式是按模型的 | 设置块里那一行标注「全局」，README 写明 |
