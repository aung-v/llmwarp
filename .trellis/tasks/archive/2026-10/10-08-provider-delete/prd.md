# 修复供应商页删除永远命中最后一个

## Goal

供应商管理页移动到删除按钮后只能删除最后一个供应商；修正删除目标的选择模型。

## 背景 / 根因

- 供应商页把「删除目标」存在 `TuiState.providerSelected`；`moveSelection` 只在光标落在供应商行时才更新它，落在 `[ + 添加 ]` / `[ - 删除 ]` 行时保留上一次的值（`src/tui/model.ts`）。
- `[ - 删除 … ]` 固定排在列表最底部，要移动到它必须先经过所有供应商行；于是 `providerSelected` 永远停在最后一个供应商——按钮文案、二次确认目标和实际删除的都是最后一个。
- 根因是交互模型：单列列表里「删除目标」无法与「光标经过的最后一个供应商」区分，必须让删除目标直接等于用户明确选中的那一行。

## 交互模型（新）

- 光标停在某个供应商行按 `Enter`，打开覆盖式操作菜单（标题为该供应商名）：
  - `编辑`（默认高亮）→ 走现有 `llmwarp edit` 流程（挂起 TUI）。
  - `删除` → 进入现有「删除供应商」二次确认；确认后调用 `removeCommand(name)`。
  - `Esc` 关闭菜单，不触发任何动作。
- 菜单内 `↑` / `↓` 选择，`Enter` 执行；菜单打开期间 `q` / `r` / `←` / `→` 一律忽略（与现有确认态一致）。
- 保留 `[ + 添加供应商 ]` 行：光标停在该行按 `Enter` 走 `llmwarp add`。
- 移除固定的 `[ - 删除 … ]` 行与 `providerSelected` 字段：删除目标 = 当前高亮的供应商行。
- 不新增单字母动作键。

## 需求

- 供应商页 `↑` / `↓` 的行范围改为 `0..providers.length`（供应商行 + 添加行）。
- 新增「供应商操作」意图：`Enter` 进入，`↑` / `↓` 在两个选项间移动，`Enter` 执行，`Esc` 取消。
- 删除沿用现有二次确认与挂起执行路径（`runSuspended` + `finishSuspended`），失败仍落到右下角反馈区。
- 自动刷新必须正确保留 / 收敛菜单状态：目标供应商消失则关闭菜单，其余情况保留。
- 渲染更新：移除 `[ - 删除 … ]` 行，操作菜单用现有确认面板样式渲染，页脚提示更新为「Enter 打开操作菜单」。

## 验收标准

- [ ] 光标停在任意供应商行按 `Enter`，菜单标题为该供应商名。
- [ ] 选「删除」后二次确认显示同一个供应商，确认后删除的也是它（不再固定最后一个）。
- [ ] 选「编辑」走原有 edit 流程；`Esc` 关闭菜单且无副作用。
- [ ] 删除失败的反馈行为与现在一致（右下角 ✗ + 原因）。
- [ ] 更新相关 TUI 断言，并新增「删除非最后一个供应商」回归测试。
- [ ] `npm run typecheck`、`npm test`、`npm run build` 通过。
- [ ] README 的供应商页交互描述同步。
