# TUI 路由页改名「模式」并说明 warp

## Goal

把 TUI 导航「路由」及其相关文案改为「模式」，并在该页说明 warp 模型名的含义，避免用户不知道其用途。

## 背景

- 该页真正控制的配置是 `useClientModel`：客户端请求体里的 `model` 名是否生效。
- 当前用户可见命名分布在：导航页签「路由」、左栏面板标题「模型路由」、右栏状态行「模型路由  …」、确认标题「切换模型路由」、页内提示「Enter 切换路由模式」。
- 页面只列出「按客户端请求」/「统一用当前模型」两种模式，却从未说明客户端可以填 `warp` 这个模型名，用户不知道它是什么、有什么用。
- 后端 `src/routing.ts` 里的 “routing” 指「模型名 → 上游供应商」的解析，与这里的开关不是同一个概念。

## 命名映射

| 现在（用户可见） | 改为 |
| --- | --- |
| 导航页签「路由」 | 「模式」 |
| 左栏面板标题「模型路由」 | 「模型模式」 |
| 右栏状态行「模型路由  …」 | 「模型模式  …」 |
| 确认标题「切换模型路由」 | 「切换模型模式」 |
| 页内提示「Enter 切换路由模式」 | 「Enter 切换模式」 |

## 需求

- 按上表替换 TUI 用户可见文案（主要在 `src/tui/render.ts`）。
- 模式页补上 `warp` 说明，至少覆盖：
  - 客户端填 `warp`（或 `model` 留空）= 用当前激活模型；
  - 客户端填 `{供应商}/{模型}` = 用该供应商的指定模型；
  - 「按客户端请求」启用上面两种写法；「统一用当前模型」忽略客户端写的模型名，一律落到当前激活模型。
- 不改变任何行为、配置项、键位或页面结构。

## 非目标

- 不改后端 `src/routing.ts` 的 `RoutingError` / `resolveModelRoute` / `routeKind` 等标识符与语义。
- 不改 `TuiState.page` 的 `"routing"` 值、`ConfirmIntent` 的 `"routing"`，也不改 CLI 文案与 `/v1/models` 内容。
- 不改 `useClientModel` 的取值语义。

## 验收标准

- [ ] 导航页签显示「模式」，左右切换仍可到达该页；左栏标题为「模型模式」。
- [ ] 右栏状态行为「模型模式  …」，确认标题为「切换模型模式」。
- [ ] 模式页可见 `warp` 与 `{供应商}/{模型}` 的含义说明。
- [ ] 该页不再出现用户可见的「路由」字样（代码标识符除外）。
- [ ] 相关渲染断言更新并通过；`npm run typecheck`、`npm test`、`npm run build` 通过。
- [ ] README 的 TUI 与接入说明同步为「模式」，并点明 `warp` 的用途。
