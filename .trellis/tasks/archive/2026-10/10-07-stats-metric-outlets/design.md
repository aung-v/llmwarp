# 设计：指标出口与契约矩阵

## 1. 展示结构（`src/tui/render.ts`）

统计页从「单面板」改成三段：

```
╭ 用量统计 ────────────────────────────────────────────╮
│ 区间 / 火花线（天或小时）                             │
│ 汇总（全局指标，保持现状 3 行）                        │
│ 过滤行（routeKind 过滤 + 未发出计数）                  │
│ ── 目标表格（选中行高亮）──────────────────────────    │
│  供应商/模型  端点  请求  错误率  平均  TTFT  p95      │
│ ── 选中目标详情 ──────────────────────────────────    │
│  延迟  p50 / p95 / 平均 / TTFT 平均 / TTFT p95        │
│  吞吐  tok/s · 流式 N · 非流式 M                       │
│  token 输入/输出/总/缓存/推理                          │
│  可靠性 错误 N · 错误率 · 中断 N · 截断 N · 拦截 N      │
╰──────────────────────────────────────────────────────╯
```

- 表格行高亮沿用现有焦点模型：统计页新增 `statsSelected`（目标下标），`↑↓` 在现有「过滤项切换」语义上扩展——过滤项用 `[]`/`Shift`？不引入新键：**`↑↓` 改为移动目标选择，过滤项改用 `←→` 在过滤行内循环**（现状 `←→` 是换页/换区）。为避免破坏既有按键约定，最终按键在实现时以 `frontend/interaction-guidelines` 为准并同步更新该 spec。
- 详情随选中行实时更新；选中的 target 在刷新后按 `provider/model/endpoint/routeKind` 重新定位（沿用 `refresh()` 里 `previousSelected` 的既有做法）。
- 表格高度不够时优先保证详情可读：详情固定 5 行，表格占用剩余空间。

## 2. 火花线粒度（`hours[]` 的出口）

- `statsMetric` 现有两态 `tokens | requests`；新增 `statsRange: "day" | "hour"`，`Enter` 仍切指标，另行提供粒度切换（具体键位同步进 interaction spec）。
- 数据源：`day` 用 `aggregate.days`，`hour` 用 `aggregate.hours`。
- `hour` 粒度为最近 24 小时（`hours` 数组尾部 24 项），避免把 30 天 × 24 小时全画进一行。
- 这样 `hours[]` 从「算了丢掉」变成真实消费者。

## 3. 契约矩阵（`.trellis/spec/backend/usage-stats.md`）

新增一节 `### 全局指标 × 维度 × 出口`，逐字段给出：

| 字段 | 支持维度 | 展示位置 |
|---|---|---|

规则：
- 矩阵必须与 `AggregateMetrics` 字段一一对应；**新增指标必须同时补矩阵行和出口**，否则视为未完成。
- 允许「暂不展示」，但必须写明理由与复查条件（例：`rateLimit` 只在响应那一刻可采、不可回溯，故先落盘；展示依赖配额面板，本期不做）。
- 反向约束：没有矩阵行的字段不得出现在 `AggregateMetrics`（可由测试断言字段集合一致）。

## 4. `rateLimit` 的处置

保持采集（上游限流头不可回溯，删掉就永久没有），但在矩阵里显式标注「暂不展示」＋理由＋复查条件。这样它从"悬空字段"变成"有记录的豁免"。

## 5. 兼容性

- `/_llmwarp/status` 载荷结构不变（不删 `hours`，反而给它出口）。
- `src/tui/model.ts` 的严格解析不变。
- 新增纯视图状态（`statsSelected` / `statsRange`）必须在 `refresh()` 里像 `statsFilter` / `statsMetric` 一样保留，避免 3 秒轮询重置用户选择。
