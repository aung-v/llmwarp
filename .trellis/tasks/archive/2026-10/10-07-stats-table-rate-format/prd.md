# 统计表格：tok/s 列 + 大数格式化 + 分位去 jargon

## Goal

让统计页在表格里就能看到真正反映上游健康的两个指标（TTFT、tok/s），并把
「一串 9 位数字」和「p95 是什么」这两个可读性问题一次解决。

## Background

- 表格当前是 `请求 | 错误率 | 平均 | TTFT | p95`，没有 tok/s；tok/s 只出现在汇总行和选中详情。
- `p95` / `p50` 是运维 jargon，用户明确表示「老是不记得是什么东西」；总耗时 p95 还混着
  「回答长度」和「服务速度」，价值低于 TTFT / tok/s，应退到选中详情。
- 真实数据里 token 输入是 `31575899` 这种 8 位数，表格与详情都不易读。

## 需求（用户已确认）

1. 目标表格加 `tok/s` 列；`p95` 从表格移除，仍保留在选中详情与汇总行。
2. 大数友好显示：计数类（请求/错误/中断/截断/拦截/未发出/样本）与 token 类
   （输入/输出/总/缓存/推理）按 `≥1000 → k`、`≥1e6 → M`、`≥1e9 → G`，保留 1 位小数并去掉多余的 `.0`。
3. 毫秒、百分比不换算；tok/s 小于 1000 保持聚合层的两位小数（`0.02 tok/s` 有意义），超过才折算。
4. `p50`/`p95` 文案改为 `50分位`/`95分位`（含 `TTFT p95` → `TTFT 95分位`）。
5. 同步 `.trellis/spec/backend/usage-stats.md` 的出口矩阵与前端 spec，并补测试。

## 明确不做

- 不动版本号（保持 1.1.0）。
- 不改任何指标的计算口径。
- 不删 `p95` / `p50` 的采集与聚合，只改展示位置与文案。
- 不把毫秒换算成秒（同一列混单位会让横向比较失真）。

## Acceptance Criteria

- [x] 目标表格含 `tok/s` 列，且不再含 `p95` 列；表格总宽不因新增列而溢出。
- [x] `95分位`/`50分位` 文案替换完成，`p95`/`p50` 不再出现在 TUI 文案里。
- [x] `formatCount`：`999 → 999`、`1000 → 1k`、`205460 → 205.5k`、`31575899 → 31.6M`、`999999999 → 1G`。
- [x] tok/s `0.02` 不被格式化成 `0.0`。
- [x] spec 出口矩阵与前端 spec 同步；`p95DurationMs` 的出口改为「选中详情」。
- [x] `npm run typecheck` / `npm run build` / `npm test` 全绿；版本号仍为 `1.1.0`。
